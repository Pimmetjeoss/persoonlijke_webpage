Wat is een MCP-server?
_ □ ×

MCP = Model Context Protocol

Een MCP-server is een soort stopcontact tussen AI en de buitenwereld.


Een AI-assistent (zoals Claude of ChatGPT) kan van zichzelf alleen praten. Wil die AI écht iets doen — je e-mail lezen, in je bestanden zoeken, het weer opzoeken, een database bevragen — dan heeft hij een poort nodig naar die tools. Dat is precies wat een MCP-server doet.


Kort gezegd:

  • 📡 Eén standaardprotocol (open source, van Anthropic)
  • 🔌 De AI koppelt zich aan de server via een vaste "stekker"
  • 🛠️ De server biedt tools, data en prompts aan
  • 💬 De gebruiker merkt er weinig van: de AI doet gewoon zijn werk

Hoe werkt het? — C:\\MCP>
_ □ ×

De drie spelers

  1. Host — het programma waar jij praat met de AI (bijv. Claude Desktop, een IDE of Discord-bot).
  2. MCP-client — zit in de host en houdt één lijn open naar elke server.
  3. MCP-server — een klein programmaatje dat specifieke mogelijkheden aanbiedt.

Het gesprek verloopt in JSON-RPC:

AI: "Welke tools heb jij?"
Server: [zoek_bestanden, stuur_email,
         haal_weer_op]
AI:     { "tool": "haal_weer_op",
          "args": {"stad": "Ede"} }
Server: { "temp": 18, "bewolkt": true }
AI: "Het is 18°C en bewolkt in Ede."

De server kan lokaal draaien (via stdio) of op afstand (via HTTP/SSE). Voor de AI maakt dat niet uit — het protocol is hetzelfde.

Waarom handig?
_ □ ×

Het probleem zonder MCP

Vóór MCP moest élke AI-app aparte integraties bouwen voor élke tool: M×N maatwerk. Rommelig en dubbel werk.


Met MCP: M+N

  • ✅ Eén standaard — elke AI-host werkt met elke MCP-server
  • ✅ Plug & play — server toevoegen = nieuwe vaardigheden voor de AI
  • ✅ Open ecosysteem — honderden gratis servers beschikbaar
  • ✅ Jij bepaalt de toegang — per server instellen wat de AI mag
